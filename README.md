# Rift Patrol

A self-contained, five-wave arcade defense game for **iOS/iPadOS 17+ and macOS 14+**, built with **Swift 6, SwiftUI and SpriteKit**. No paid assets, network service, account or API keys are needed.

## Play

Defend the van from ghosts pouring through the rift. Hold a finger or mouse button over ghosts to fire continuously; aim at their centers for critical hits. Earn scrap from kills and quick kill chains, then spend it on up to four automatic companion turrets:

- **Tesla — 40 scrap:** rapid single-target fire.
- **Mortar — 70 scrap:** area damage against clustered ghosts.
- **Pulse — free, 18-second recharge:** damages every ghost on screen. It is ready at the start of each patrol.

Ghosts that reach the van deal 10 damage. Survive all five waves to seal the rift; lose all van health and the run ends. Buy companions during combat or the short wave breaks. The pause screen lets you resume or start over, and the game pauses when the app leaves the foreground. Best kill count and sound preference are saved locally; an unfinished run is not saved across app termination.

The game includes a title screen, animated neon arena, shielded enemies, critical hits and combo rewards, visible turret companions, particles and damage popups, synthesized sound effects with a mute button, and victory/defeat screens with instant replay. On Mac, **Space** activates Pulse and **P** or **Escape** pauses/resumes.

## Run on iPhone or iPad using Xcode

You need a Mac with **Xcode 16 or newer**, its iOS platform support installed, and a checkout of this pull request's branch (the project is not on `main` until the pull request is merged).

1. Open **`RiftPatrol.xcodeproj`** from the repository root. There is no need to create an app or copy source files.
2. Select the **RiftPatrol-iOS** scheme in Xcode's toolbar.
3. Choose an installed **iPhone or iPad simulator** as the run destination. If none is installed, use **Xcode → Settings → Components** (called **Platforms** in some Xcode versions) to install iOS support.
4. Choose **Product → Run** or press **Command-R**. Tap **START PATROL** in the game.

For a physical device, select the blue project icon → **RiftPatrol-iOS** target → **Signing & Capabilities**, choose your own development team, and change the bundle identifier from `dev.ghostchat.riftpatrol` to one unique to you. Connect and trust the device, select it in the toolbar, enable Developer Mode on the device if prompted, and press **Command-R**. Simulator builds do not need a development team.

The app uses a portrait arena and supports iPhone and iPad. The scene fits within the available view with black letterboxing where necessary; it does not stretch gameplay. `Info.plist` is generated by the project, including scene and launch-screen metadata and portrait orientation. **No privacy permission keys or special capabilities are required.**

The Xcode app target compiles the existing `Game/` files and links the local `RiftPatrolCore` package from this repository; there are no duplicate game sources or remote package dependencies. Keep the whole repository together when moving it. Open the project by itself rather than adding it to a workspace that already contains this package.

## Run on a Mac

Install Xcode with a Swift 6 toolchain, open Terminal in the repository root, and run:

```sh
swift run RiftPatrolGame
```

Alternatively, open `Package.swift` in Xcode, select the **RiftPatrolGame** scheme and **My Mac**, and press **Command-R**. Use the mouse to hold and drag over ghosts and the on-screen buttons to buy turrets, use Pulse, pause, restart or toggle sound.

## Tests and build checks

From the repository root:

```sh
swift build
swift test
swift run RiftPatrolSim 20
```

Build the iOS application for the simulator without device signing:

```sh
xcodebuild -project RiftPatrol.xcodeproj \
  -scheme RiftPatrol-iOS \
  -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

GitHub Actions builds the Mac package, runs core XCTest tests and the deterministic battle simulator, and separately builds the iPhone/iPad app for iOS Simulator. The core tests cover shields, critical hits, finishers, combo timing, purchases, session victory/defeat and deterministic simulation. A successful simulator **build** is not an automated launch or touch/audio playtest. The command-line simulator uses the core model, not the SpriteKit input/rendering loop.

### Manual device acceptance checklist

- Start a patrol on iPhone and iPad; check that the title, arena and buttons fit without clipping.
- Hold and drag to fire; verify center hits, shields, kill effects and combo rewards.
- Buy both turret types; check automatic fire, mortar splash damage, scrap costs and the four-slot limit.
- Activate Pulse, verify its cooldown, and toggle sound both ways (also test with device audio enabled).
- Pause/resume, background/foreground the app, restart mid-wave, and check that enemies do not advance while paused.
- Play through victory and defeat; replay, then relaunch to verify saved records and sound preference.

## Scope

This is a complete small arcade game, not an App Store distribution package. Art and effects are drawn in code; sound effects are synthesized. It does **not** include physics ragdolls, a music soundtrack, story campaign, online features, controller support, a custom app icon, or App Store screenshots/marketing assets. Publishing requires your own signing setup, distribution assets and physical-device QA.

On Linux, core logic can run without SpriteKit; the game executable only prints the Apple-platform requirement.
